# 新黑苹果生态调研：从 OpenCore 到「虚拟 Apple GPU」

> 调研对象：steelbrain 的五个仓库 + 本工作区 fork（Hi-Jiajun/reims-vgpu）
> 调研时间：本工作区建立时（upstream master = d8c3a75，2026-08-27）

## 1. 背景：黑苹果为何会终结，这条新路线为何重要

传统黑苹果 = OpenCore/Clover + Intel Mac 兼容硬件 + Apple 对 Intel 平台的 macOS 支持。
Apple Silicon 转型后，macOS 对 Intel 的支持线正在收尾，传统路线注定终结。

但这几个项目发现了另一条路：Apple 自己的虚拟化框架 Virtualization.framework（VZ）
留给 macOS 一套**半虚拟化 GPU 驱动**——`AppleParavirtGPU.kext`。它是 macOS 系统自带、
供 VZ 虚拟机使用的。steelbrain 的项目把这套驱动变成了一个通用虚拟 GPU 的**客户机端**：

- **客户机零改动**：不注入 kext、不修改系统，只用 macOS 自带的驱动；
- **宿主机实现设备**：QEMU 设备 + Rust 后端，解码 Apple 私有的 paravirt GPU 命令流，
  用宿主机的 Metal 或 Vulkan 渲染；
- **着色器翻译**：客户机提交的是 Metal AIR（LLVM bitcode），由 metal2vulkan 翻译成
  Vulkan SPIR-V。

这就是"新黑苹果"的完整形态：任何能跑 QEMU 的宿主 + 一个虚拟 GPU 设备 + 合法获取的
macOS 镜像，即可获得带 GPU 加速的 macOS 虚拟机。

## 2. 五个仓库及其关系

| 仓库 | 角色 | 许可证 | 状态 |
|---|---|---|---|
| experiment-macOS-arm64-on-linux-x86（代号 27on86） | 证明 arm64 macOS 客户机在 x86-64 宿主上用 QEMU TCG 软件翻译可引导 | — | M0–M2 完成（macOS 13 可重复引导、8 vCPU、SSH 可用），M4 进行中 |
| experiment-macOS-arm64-on-asahi-linux-arm64 | Apple Silicon + Asahi Linux 上用 KVM 加速引导 arm64 macOS，带图形桌面 | — | 已知良好配置可跑通（M2 Pro / Fedora Asahi / macOS 13.6） |
| qemu-reims-vgpu | QEMU 分支：vmapple 机型 + 薄 C 设备壳（reims-vgpu-mmio/pci） | GPL-2.0-or-later（QEMU） | 活跃，关键分支 host-reims-vgpu-vmapple |
| metal2vulkan | Metal AIR（LLVM bitcode/IR）→ Vulkan 1.3 SPIR-V 翻译器 | LGPL-3.0-or-later | Alpha，Rust 库 + CLI |
| reims-vgpu | 主项目：协议解码、设备模型、Metal/Vulkan 后端、C ABI | LGPL-3.0-or-later | Alpha，活跃（PR #50 后） |

关系：reims-vgpu 通过 git submodule 引用 qemu-reims-vgpu（分支
host-reims-vgpu-vmapple）；qemu-reims-vgpu 的 hw/display 下是薄 C 壳；C 壳通过版本化
C ABI（`reims_vgpu_qemu_abi.h`，当前 v17）把 QEMU 静态链接进 Rust 产品库
（crates/reims-vgpu，`crate-type = ["staticlib", "rlib"]`）；产品库的 Vulkan 后端依赖
metal2vulkan 翻译着色器。27on86 与 Asahi 实验是外围验证项目，产出对 QEMU/reims 的补丁。

## 3. 总体架构

```text
┌──────────────────────── macOS 13+ 客户机（未修改）────────────────────────┐
│ WindowServer / Metal.framework（提交 Metal 命令流 + AIR 着色器）           │
│ AppleParavirtGPU.kext（Apple 自带，与 VZ 用同一个驱动，无需注入）          │
└─────────────────────────────┬────────────────────────────────────────────┘
                              │ 私有 paravirt 协议（wire 格式）
┌─────────────────────────────▼────────────────────────────────────────────┐
│ QEMU（qemu-reims-vgpu 分支）                                              │
│   vmapple 机型（arm64 客户机）/ 普通 pc 机型（x86_64 客户机）               │
│   reims-vgpu-mmio / reims-vgpu-pci —— 薄 C 壳：QOM、MMIO/BAR、IRQ/MSI、   │
│   console、HostOps（客户机 RAM 访问）、脏页适配器                            │
└─────────────────────────────┬────────────────────────────────────────────┘
                              │ 版本化 C ABI（进程内静态链接）
┌─────────────────────────────▼────────────────────────────────────────────┐
│ reims-vgpu Rust staticlib                                                 │
│   decode（wire 零拷贝视图）→ 设备模型 → 调度 → 后端执行                      │
│   ├─ Vulkan 后端：自含 ash 引擎 + metal2vulkan（AIR→SPIR-V）               │
│   └─ Metal 后端：仅 macOS 宿主（默认特性 backend-metal，别处编译报错）      │
│   内存 rails：host-pointer 导入 / 拷贝 / 打包视图                            │
│   观察性：/tmp/reims-vgpu-fail.log（fail/off 双通道、typed decline）        │
└─────────────────────────────┬────────────────────────────────────────────┘
                              │
                    宿主机 GPU：Vulkan ICD / Metal
```

## 4. 关键技术事实（调研确认）

### 4.1 三条一等通路（first-class pathways）

| 通路 | 宿主 | 客户机 | 设备 | 页大小 | 后端 | 启动脚本 |
|---|---|---|---|---|---|---|
| x86 macOS / Linux Vulkan | Linux x86_64 (KVM) | x86_64 macOS | PCI `reims-vgpu-pci` | 12 | Vulkan（metal2vulkan） | vm/boot-x86.sh |
| arm64 macOS / macOS Metal | Apple Silicon macOS (HVF) | arm64 macOS | sysbus MMIO `reims-vgpu-mmio` | 14 | Metal 直连 | vm/boot-arm64.sh |
| arm64 macOS / macOS Vulkan | Apple Silicon macOS (HVF) | arm64 macOS | sysbus MMIO `reims-vgpu-mmio` | 14 | Vulkan via MoltenVK | vm/boot-arm64.sh |

### 4.2 内存 rails（AGENTS.md「Support Matrix」）

- **host-pointer 导入**：`VK_EXT_external_memory_host` 把 QEMU RAMBlock 的宿主指针直接
  导入 Vulkan。AGENTS.md 原文写明该原语覆盖「**Linux 和 Windows**」（macOS 经 MoltenVK，
  Metal 直连经 `newBufferWithBytesNoCopy`）。dma-buf 路线已被刻意删除——它是 Linux 内核
  对象，Windows 没有等价物（`VK_KHR_external_memory_win32` 移动的是 NT handle，不是任意
  宿主指针）。
- **拷贝 rails**：没有导入能力的宿主（或 `REIMS_VGPU_GUEST_IMPORT=off`）走拷贝路径，
  逐字节正确但慢（实测 ~1/2 帧率、3x 每 draw 成本）。**这是 Windows 上的保底路径。**
- **打包视图（packed view）**：客户机一个线性虚拟资源可能指向散乱的客户机物理页；
  macOS 壳用 mach_vm，Linux PCI 壳用 mmap+memfd 造连续别名。Windows 目前没有实现
  （runtime/host.rs 的 alloc_block 只有 macOS 臂 + 其他平台臂；PCI 壳里 248-285 行是
  Linux mmap）。Windows 上退化为 gather/copy。
- **脏页 witness**：hypervisor dirty bitmap + 设备自己的逐页写记录双重见证。
  依赖 QEMU 的 dirty-log sync（需 BQL）。

### 4.3 平台耦合点（Windows 移植相关，全部核对过源码）

- Rust 产品代码里**没有 Linux 专属 cfg**，只有 macOS 专属（Metal 后端、窗口主线程、
  mach_vm 打包视图）。
- `backend/vulkan/engine/context.rs`（约 690-720 行）按平台挑选 surface 扩展：
  macOS → metal_surface；Linux → xlib/xcb/wayland；**其他平台 → 空数组**。
  Windows 需要加 `VK_KHR_win32_surface` 臂（改动很小，加错会被 typed decline 接住）。
- `host_window/present.rs`：窗口线程模型跨平台（winit 0.30 + ash-window +
  raw-window-handle 本身就是跨平台栈），只有 macOS 有主线程特例。
- QEMU 侧 hw/display/meson.build：`reims_vgpu_rust_sys_libs = ['-lm', '-ldl',
  '-lpthread']` 是 Unix 专属链接参数，Windows 需要新臂；Metal 框架链接仅 Darwin。
- PCI 壳里唯一的深 Linux 依赖是 mmap 打包视图（可降级）；没有 KVM 专属 API 调用。

### 4.4 加速器依赖

- vmapple 机型：上游文档只写 Apple Silicon + HVF（macOS 12+ 宿主）。27on86 项目证明
  拆掉 HVF 假设后 TCG 可跑（x86-64 宿主，8 vCPU 可重复引导 macOS 13）。
- Asahi 实验证明 KVM 可行，但需要**内核补丁**保存/恢复 Apple 私有的指针认证 VM key
  （APCTL/KERNKEY）等状态——说明这套状态不在标准 ARM KVM 上下文里，**WHPX 同理不具备**。
- qemu-reims-vgpu 的 `steelbrain/macos-arm64-fixes` 分支（tip b625176）包含大量
  TCG 翻译器修正 + vmapple RFC v7 补丁 1-6 + reims 壳的近期提交，是 27on86 风格工作的
  直接参考；其中对 `target/arm/whpx/whpx-all.c` 已有小改动（guest debug 支持 stub）。

### 4.5 开发纪律（AGENTS.md 摘要，贡献前必读）

C 只做薄壳；契约是唯一输入（禁止启发式/旁信道）；永不静默失败（typed decline +
fail log）；测试定义完成；测量先于修复；不 grep 源码做验证；子代理只读；boot 验证
协议（n≥3、区分 panic/freeze/慢 boot 群体、读 fail log 双通道、present_hz 与
offered_hz 成对读）。

## 6. 边界与合规（与上游一致的规则）

- 固件（AVPBooter）、IPSW、恢复镜像、VM 磁盘、VM 身份、日志、OpenCore/OVMF 运行时
  **永不入库**；
- 不传播 macOS、不绕过 Apple 恢复签名；
- macOS 的合法获取与虚拟化许可限制由使用者自负（EULA 通常只允许在 Apple 硬件上
  虚拟化 macOS；研究代码本身不提供任何受版权保护的材料）。
