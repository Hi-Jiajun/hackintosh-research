## 2. metal2vulkan `43c46ac`：值得参考的内容

规模：`9e0e99a` → `43c46ac`，772 files changed，+71,388/−11,492；`REFLECTION_VERSION` 从 41 升到 55。

### 2.1 Reflection / descriptor 正确性

- 新增 `NonWritable` decoration 与 `src/reflect/nonwritable.rs`，由完成后的模块证明 buffer/image 是否可写；这会影响通用 shader 的读写方向判断。
- descriptor array/count、静态采样器排序、render target location、`air.location_index` 描述符计数等修复；这些字段会被 provider 的 descriptor layout 直接消费。
- `ResourceKind::SynthesizedReadSampler` 的状态现在由 `StaticSamplerState` 描述：消费者必须绑定 nearest sampler，否则 `texture.read` 的精确 texel 语义会被线性过滤破坏。

### 2.2 翻译覆盖面

- AIR intrinsic lowering、access-chain/pointer 处理、dynamic memcpy、structured CFG、subgroup materialize、loop budget、aliased imageblock、imageblock block copy、shuffle 等新 lowering。
- function-constant folding 更完整；当 folding 抹掉模块的全部可观察写入时，新增 typed refusal，而不是静默输出无效模块。
- 只写 imageblock 的模块新增 typed refusal：Vulkan 没有 tile resolve，不能假装它写入了 attachment。

### 2.3 验证体系

- Metal/MoltenVK oracle、observation contract、triage、corpus pipeline。
- 新增多组 fuzz 套件：access、gpu、inline、irreducible、pointer_select、structured、workgroup。
- 这些 refusal 和 oracle 的组织方式可作为我们 provider admission/结构化错误的设计参考。

### 2.4 对本项目的直接影响

- 当前 `metal-api-vulkan` 只接受 `ResourceKind::Buffer`，因此 `SynthesizedReadSampler` 暂不影响现有用例。
- 未来 texture/sampler 路径必须把 translator 合成资源当作一等公民，并按 reflection 绑定 nearest sampler。
- 新 refusal（function-constant erased effects、imageblock-only）应映射为 provider 的结构化 refusal，不能 panic 或退化成通用错误。
- `BufferFootprint`、descriptor 计数和 `NonWritable` 的变化会影响通用 shader admission；当前受限 fixture 未受影响。
- loop budget instrumentation 可作为 shader admission 的资源上限/DoS 防护参考。

## 3. reims-vgpu：master 未变，PR 值得跟踪

### 3.1 PR #80（2026-09-07，open）

`fix(vgpu): carry the translator's read sampler in the reflected sampler interface`

- 问题：`texture.read` 让 metal2vulkan 合成 `SynthesizedReadSampler`，但 reims 的 `reflected_sampler_binding` 只接受 `Sampler`/`StaticSampler`，该 descriptor 被从 executable variant 的 sampler interface 中丢掉，导致 compute dispatch refusal，并伴随 WindowServer hang。
- 文件：`runtime/spirv_bind.rs`、`runtime/m2v_cache.rs`、`runtime/compute_exec/vulkan.rs`、`runtime/draw/vulkan.rs`。
- 启示：provider 的 reflection→descriptor 映射必须覆盖 translator 合成资源；这与“canonical path 只消费同一份 reflection contract”的方向一致。

### 3.2 PR #79（2026-09-08 更新，open，stacked on #78）

`fix(vgpu): settle queued guest writes before the guest takes its pages back`

- 问题：sustained compositing（窗口拖拽，约 100 Hz present、6000–8000 draws/s）下，guest 页回收与 direct guest-write rail 的排队写回发生 ordering 漏洞，guest kernel panic；`REIMS_VGPU_GUEST_IMPORT=off` 可隔离。
- 文件：`runtime/drain/mod.rs`、`runtime/render_writeback/*`、`runtime/compute_exec/vulkan.rs`、`crates/reims-vgpu-core/src/depend.rs`、`runtime/mapper/mod.rs`。
- 启示：provider completion 必须与 writeback landing、page 生命周期绑定；这正是我们“异步提交/结果回收 + 真实 guest memory 生命周期”缺口的现实证据。

### 3.3 PR #78（open）

`perf(core): compact the dependency graph once retired slots outnumber live ones`

- `DependencyGraph::retire` 只清 `live` 标志，不压缩索引，导致 `admit` 成本随会话时长增长。
- 与 provider 接口无直接冲突，但属于 neutral model 的寿命/性能前提；可参考其“retired 超过 live 时压缩”的触发策略。

### 3.4 其他

- PR #77（VNC 稳定性）、#62（integrated GPU topology）、#46（guest cursor）、#47（dGPU perf rewrite）与本 provider 计划无直接关系。

### 3.5 我们的可选适配器状态

- `integration/reims` 在 metal2vulkan pin 升级后曾无法编译：适配器把 43c46ac 的 `KernelDispatch` 传给了 vendored reims 的 9e0e99a API。`6e5df5b` 改为用当前 reflection 的 `validate`/`push_constant_range`/`plan` 直接构造 `ComputeDispatch::Regions`；两版 region 与 48-byte payload ABI 相同。
- 本地验证：3 个适配器单测通过，Lavapipe `reims-smoke` 的 `copy_word`、raw/wrapped binary AIR、`indexed_boundary_dispatch`（30 words / 4 regions）与 suite executor 全部 PASS；证据在 `evidence/reims-bridge-6e5df5b-2026-09-08/`。该 workspace 仍不在根 CI 中，且不构成生产 guest/display 接入。
