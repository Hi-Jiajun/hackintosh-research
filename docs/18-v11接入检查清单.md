# v11 纹理用例接入检查清单（2026-09-14）

> 前置条件已全部就绪（`docs/16` §4.9）：translator 反射、core 契约/trace/wire、Vulkan 执行、
> 对象 API 绑定都有双驱动证据。本文是 v11 落地的逐步清单，按顺序执行，每步独立可验证。

## 当前阻断点

`conformance/suite-v*.json` 的用例格式只描述 buffer（`buffers[]` + `expected_writebacks[]`），
而 `provider-capture` 与 `compare.py` 也只认识 buffer 轨道。纹理用例要进来，先扩展这三处；
**注意**：`tools/lavapipe-smoke.sh` 会自动发现 `suite-v*.json` 并跑全部轨道，所以
**不能先把 suite-v11.json 放进去再补工具**，否则本地与 CI 门禁会立即变红。正确顺序如下。

## 步骤

1. **case schema**：`suite-v11.json` 增加纹理段（参考 `docs/16` §4.2 与 metal2vulkan 的
   `validation/corpus/cases/*.jsonl` 的 `textures` 字段：binding/dimensions/format/role/
   bytes_hex），并在 `conformance/README.md` 记录新字段。
2. **capture 工具**：`provider-capture` 支持从 case 构造 `TextureView` 并走对象 API 的
   `set_texture`；先只做 direct 轨道（快照路径已有纹理执行）。
3. **比较器**：`compare.py` 把纹理采样结果作为 buffer 观测（采样值已经写入输出 buffer，
   第一版不需要新的观测面），并允许 case 携带 `textures` 段。
4. **三路径**：direct / objects / objects-async 全绿后，再把 v11 加进 smoke 的自动发现
   （此时 `suite-v11.json` 已可安全提交）。
5. **Swift oracle（跨日，macOS）**：`conformance/NativeOracle.swift` 增加纹理读取用例，
   五路径 `compare-captures` 才会要求 v11 一致；在此之前 CI 里 v11 只做三路径说明。
6. **证据**：Lavapipe 与 RTX 5060 真机跑 v11，按惯例归档
   `evidence/conformance-v11-<hash>-<date>/`。

## 验收

- v1–v10 字节 parity 不变；
- v11 三路径（Lavapipe）与 RTX 5060 真机全 PASS；
- `compare.py --suite suite-v11.json --check <capture>` 通过；
- 若 Swift oracle 已就绪：五路径 compare 通过并归档。

## 不要做的事

- 不要用多 invocation 纹理用例（上游缺陷未决，`docs/17`）；
- 不要在工具支持前提交 `suite-v11.json`（会让门禁变红）；
- 不要修改 v1–v10 的任何用例或比较语义。
